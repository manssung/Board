# 증권사 XML 입력 구조 비교 분석

분석일: 2026-10-15 (한국 시간)

## 결론

7개 증권사 데이터셋은 같은 CONTROL 기반 구조를 사용한다. 공통 해석기와 공통 화면을 만들고 구조별 예외를 추가하는 방향이 적절하다. 현재 KB 해석기를 이름만 바꾸어 전 조건에 적용하는 것은 적절하지 않다. 라디오별 필드 활성화, 다중 문장 템플릿, 체크박스, 달력, 원본 조건 식별을 보완해야 한다.

## 분석 범위와 수치 해석

brokerMap에 등록된 map XML만 분석했다. 원본 템플릿에는 선물·옵션, 중복 정의, 카테고리 노드도 포함되어 화면의 조건 수와 다르다. 아래 현재 규칙 해석 수치는 DOM 구조를 처리할 수 있다는 뜻이며 HTS의 동작이나 모든 값의 유효성을 대조 검증했다는 뜻이 아니다. 현재 KB 전용 거래대금 예외는 다른 증권사에 적용하지 않았다.

검토 대상으로 집계된 것 중 639개는 수정할 항목이 없는 고정 문장이므로, 별도 입력 UI 없이 표시하는 분류를 추가하면 된다. 나머지 검토 대상 전체가 개별 수작업을 요구하는 것은 아니며 여러 항목이 동일 구조 규칙을 공유한다.

## 공통 구성

- Edit → 숫자 입력: 기본값, 입력 길이, 부호, 소수 자릿수 규칙을 보존한다. 소수 허용 여부를 기본값만으로 추측하는 현재 방식은 명시된 속성과 대조해야 한다.
- ComboBox → 드롭다운: COMBO_ITEM과 COMBO_INDEX를 묶고, 목록이 비어 있거나 외부 조회형이면 임의 선택지를 생성하지 않는다.
- Radio → 단일 선택: PACKET_ID와 RADIOGROUP_ID로 그룹을 나누고, 선택된 분기에 속하는 필드만 활성화한다.
- Check → 독립 선택: 여러 체크값 조합과 결과 문장 합성 규칙을 별도로 다룬다.
- Calendar → 날짜 입력: 숫자 입력과 구분하고 원본 날짜 형식을 유지한다.
- Static / DivideLine → 문구·단위·구획: 레이아웃 좌표는 보조 증거로만 사용한다.

## 먼저 보완할 구조 규칙

| 규칙 | 실제 확인 사항 | 처리 방향 |
|---|---|---|
| 라디오별 문장 전환 | COMPLETE_INDEX_NAME와 COMPLETE_INDEX_NAME2가 다름 | 분기 값과 문장 템플릿을 명시적으로 연결. 순서만으로 추측 금지 |
| 라디오 옆 문구 | STATIC_CAPTION이 없는 Radio가 다수 존재 | 그룹과 연결된 Static/ComboBox에서 문구를 구성. 좌표만으로 단정 금지 |
| 입력칸 활성화 | RADIOGROUP_ID가 있는 Edit/ComboBox, 일부 누락된 항목 | 확실한 그룹만 활성화. 누락된 연결은 구조별 보정 규칙 필요 |
| 체크 조합 | LS의 Check 컨트롤은 원본 템플릿 261개에서 확인 | 독립 선택과 라디오를 구분하고 결과 합성 규칙 추가 |
| 원본 연결 | 같은 이름·태그가 다른 파일과 상품군에서 재사용됨 | 증권사 + 파일 + 태그/ID로 식별. 이름만으로 자동 연결하지 않음 |

## 검증·적용 기준

1. XML 파싱 → 공통 스키마 → UI 렌더링 → 원본 템플릿으로 결과 생성이라는 한 경로를 사용한다.
2. 표시할 필드가 아닌 기존의 봉 주기·발생 횟수 등 공통 설정은 덮어쓰지 않는다.
3. 기존 문장을 구조화 값으로 읽지 못하면 기본값을 자동 적용하지 않는다.
4. 각 구조의 대표 XML, 모든 분기, 적용/취소/재열기, 잘못된 범위와 단위에 대해 검증한다.
5. 처리 가능한 구조만 전 증권사에 일괄 활성화하고 미해석 항목은 기존 편집을 유지한다.
6. 전 항목이 확인되기 전 전체 지원 또는 HTS 동일 동작으로 표시하지 않는다.
